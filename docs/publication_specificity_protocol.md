# Task-Specificity And Answer-Boundary Protocol

Protocol: `retrieval-specificity-v1`, implemented 15 October 2026 before pretrained-model outcomes. This is a repository experiment plan, not an externally registered preregistration. The earlier confirmation and temporal runners, configurations, and results are unchanged.

## Questions And Design

The temporal study found later-token score effects but no complete donor-answer transfer. This follow-up asks whether the selected heads' effects depend on long-distance retrieval, and whether the core group's apparent support depends on how the answer begins. It adds a known-positive transfer calibration to distinguish sparse-patch outcomes from an inability to reproduce donor generation at all.

The fixed configuration is `configs/publication_specificity.json`. It retains Qwen2.5-1.5B-Instruct revision `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`, the earlier tokenizer/chat fingerprint, bfloat16, SDPA, the original head groups, and all five original layer/count-matched control draws. Group indexing is preserved before filtering; active or overlapping controls are not discarded.

Two panels share the far-chat condition rather than crossing every factor:

| View | Context | Interface | Corruptions | Panel |
| --- | --- | --- | --- | --- |
| `far_chat` | Approximately 8K, fact early | Chat | Different first digit; shared first digit | Distance; boundary on different-first cases only |
| `near_chat` | Same tokens/length as far, fact moved nearby | Chat | Both | Distance, including local ablation controls |
| `short_chat` | Fact, distractor, and question; no filler | Chat | Both | Distance, including local ablation controls |
| `far_raw` | Same far document | Raw, no added answer separator | Different first digit | Boundary |
| `far_raw_space` | Exactly the raw prompt plus one trailing space | Raw with explicit answer boundary | Different first digit | Boundary |

The source/query wording, answers, distractor, and filler strings are paired within identity. Far/near reorder the same uniformly separated text blocks and must have **exactly equal token counts**. The nearby fact remains before the unrelated distractor note and question; their order is not reversed. Raw and space-separated raw differ by exactly one appended space. Chat wraps the same task body.

The five legacy variants are retained: literal, alias, paraphrase, relational, and distractor-heavy. Both corruption types are answer-only substitutions. The shared-first condition shares exactly one leading answer token and differs at digit two. Candidate answers are six single-digit tokens with stable prompt-continuation boundaries in every relevant view. Each identity uses the same corruption answer across its views. No truncation is allowed.

The short view deliberately retains the same instructions, including the introductory wording, while removing filler. Far/near changes source position and source-query distance; it does not independently identify an abstract distance mechanism. Near/short changes context length and irrelevant content, not only distance. These distinctions must remain explicit in interpretation.

## Interventions

### Distance panel

Patch the frozen L22H7 group and the three-head address group, plus each group's five controls, at either:

- `prompt_only`: the final prompt position predicting the first answer token.
- `prompt_and_decode`: that position and all subsequent free-generation positions, including EOS prediction.

These are the previously tested temporal operations. The new runner delegates their execution to the unchanged temporal scorer. Donor and recipient consume the same prefix actually generated by the recipient, with separate caches. Neither document prefill is intervened on. Teacher-forced clean/corrupt/decoy scoring branches are isolated from one another and from greedy generation.

### Ablation: distance and boundary panels

On clean recipients, intervene at the final prompt position only. Test the original 16-head non-address core and three-head address group, with five controls each, on **all five views** in the different-first stratum. Thus the core's far/near/short task specificity is measured directly, as well as its raw/raw-space/chat boundary sensitivity. Use:

- **Zero ablation:** zero selected `o_proj`-input head slices.
- **Task-matched resampling:** replace those slices with one fixed, fresh reference identity's unmodified final-query activations. The reference has the same variant, distance condition, context-length target, and prompt interface, but its own fact, query details, answers, and filler. The same reference identity is paired across all five views. All focal/control groups use that reference without outcome-based selection.

Resampling is a nonzero replacement control, not a content-free intervention. It may inject another answer or other task information. Generated reference-answer matches are saved separately. A single replacement draw per identity does not average over every possible resampling donor. Do not call zero/resample differences proof of a pure formatting or retrieval role.

A resampling reference is **not** a dynamically aligned decoding donor. Its query activation is captured once and reused at the recipient's query position, then the intervention is removed. Reference length, query position, final input token, seed, prompt, and hash are recorded. The reference may have a different total token length; no fabricated alignment is asserted. Per-step traces distinguish cached-reference reuse from an actual aligned donor forward.

### Positive transfer calibration

For **every case**, run the unpatched clean-context donor with the recipient's actual prefix and replace the recipient's **entire residual vector at the input to the final Qwen normalization layer** at every prediction step. This is after the transformer blocks, not an attention-head or prefill intervention.

At each step, the resulting recipient logits must match the current donor logits to maximum absolute error at most `1e-5`. Both final-normalization hooks must fire exactly once. The full generated token sequence, stopping condition, generated-token scores, and all three teacher-forced candidate score sequences must reproduce the unpatched clean baseline within `1e-5`.

The target is the donor's **actual generation**, including an incorrect answer or token-budget stop when that is what the donor does. The runner never feeds the known gold answer into the free-generation branch. This is deliberately a broad output-side calibration, not a newly discovered sparse circuit, evidence of retrieval specificity, or an accuracy intervention for the corrupted recipient document.

Each case also includes clean/corrupt head self-patches using the union of the heads used in that case, at both scopes for distance cases and at prompt-only for raw boundary cases. They must preserve baseline outputs and per-token scores. A self-patch verifies preservation; the residual control verifies donor reproduction.

## Readouts And Analysis

All rows preserve the original three candidate scores (clean, corrupt, unrelated decoy), every token log-probability, per-step traces, full generated text/token IDs, and EOS/budget termination. Candidate scoring covers the six digits, not EOS. The free-generation budget is **64 tokens**, increased from the temporal run's 24 to give raw/explanatory responses more room. Budget-limited outputs remain recorded; a budget stop is not EOS or a complete answer.

Keep these measures distinct:

- `exact_clean`: the established six-digit answer comparison after trimming outer whitespace.
- `verbatim_clean`: the generated text equals the six digits with no trimming.
- `clean_number_content`: one or more occurrences of the correct six-digit number, with no other six-digit number.
- `six_digits_only` and `generated_leading_whitespace`: output-format diagnostics.
- `exact_resample` and `resample_number_content`: matching the fresh resampling source's answer, when one is defined.
- Donor prefix/suffix measurements: token-position diagnostics, not substitutes for complete answer transfer.

The prepended prompt space in `far_raw_space` is input context, not a generated token. Raw-space and chat manipulate different aspects of the interface; they must not be collapsed into one repair condition. Candidate scores condition on supplied candidate prefixes, not necessarily the greedy trajectory. Three scored candidates do not exhaust possible wrong outputs.

The analyzer validates the complete case/condition/reference grids; source, file and prompt hashes; frozen groups; reserved identities; body/answer/space-only edits; exact far/near lengths; candidate arithmetic; generation metrics; reference mapping; and every recorded scope, prefix, position, hook and positive-logit check. Missing, inconsistent, nonfinite, or failed positive/self-control evidence prevents a passing run.

The summaries report each view, corruption, condition and variant separately. The paired analysis resamples identities within variant with 4,000 percentile-bootstrap draws, preserving all repeated measures and attached reference donors. Main readouts are clean-answer token-score change, exact-answer change, and correct-number-content change. It reports:

1. Focal-minus-mean-matched-control effects in each view.
2. Far-minus-near and far-minus-short **control-adjusted interactions** for both sparse patching and zero/resampled ablation, not comparisons of unrelated batches.
3. Combined-minus-prompt-only control-adjusted patch effects.
4. Raw-space-minus-raw and chat-minus-raw control-adjusted boundary interactions.
5. Resampling-minus-zero control-adjusted contrasts.

Intervals are 95% pointwise, conditional on the fixed head draws, with no multiplicity adjustment. Forty identities is a diagnostic budget, not a power calculation. Zero-event intervals do not establish zero population risk. Preserve all task failures; do not select successful examples for the primary analysis. Smoke gating checks computation/provenance, not the hoped-for scientific effect or perfect task accuracy.

## SageMaker Commands

Use the existing activated `rha-venv` from the repository root. No new dependencies or CUDA/PyTorch upgrade are required. Pull the committed code before running; uncommitted experiment sources are rejected. Do not edit source/config files while a run is active.

### Smoke

```bash
git pull --ff-only
mkdir -p logs
set -o pipefail

python -u scripts/run_publication_specificity.py \
  --stage smoke \
  --out-dir artifacts_publication/specificity_smoke_8192 \
  2>&1 | tee logs/specificity_smoke_8192.log
```

Expected completion is **`PASS: 1580 rows`**, including 40 passing positive-control cases. Inspect baseline counts as well: raw formatting and content need not be perfect for the computation to pass. If task behavior is unexpectedly poor, inspect the retained smoke evidence before the full run. Do not filter failures or tune the head set to obtain a preferred effect.

### Full confirmation

```bash
nohup python -u scripts/run_publication_specificity.py \
  --stage confirmation \
  --smoke-dir artifacts_publication/specificity_smoke_8192 \
  --out-dir artifacts_publication/specificity_confirmation_8192 \
  > logs/specificity_confirmation_8192.log 2>&1 &

tail -f logs/specificity_confirmation_8192.log
```

Expected completion is **`PASS: 12640 rows`**, including 320 passing positive-control cases. The full run re-audits the smoke and requires matching protocol, source hashes, packages, model revision and chunk size. A code/environment change requires a new smoke. Ctrl-C stops `tail`, not the background job. Use the smoke's actual runtime to budget the full run: it has eight times the case work, with different fixed loading overhead. No unmeasured GPU runtime is promised.

Each row is flushed immediately and the manifest is checkpointed after each case. Failures and interruptions retain partial outputs with status `failed`. There is no overwrite, append, or resume path that could silently combine incompatible runs.

Fetch both complete run directories, including all seven files:
